# 控制周期与示教记录恢复

## 控制周期 DT 监测

当控制周期有效且超过 `safety_policy.max_dt_s` 时记录一次超限

连续三次超限才触发 `INVALID_DT` 和 FAULT

只要中间出现一次合格控制周期就清零连续超限计数

零值 负值 非有限时间差以及时间戳回退仍然立即视为异常

电机掉线 状态过期 越界以及其他安全故障不受三次计数规则影响

FAULT 仍要求人工检查并显式清除 不会自动解除或继续轨迹

## 示教记录与检查点

示教开始后约每 2 秒保存一次 `trajectory.checkpoint.csv`

正常结束后另外原子保存 `trajectory.csv`

记录由采集线程保存而不是控制周期线程

结束时的完整轨迹优先于未完成检查点

故障前检查点只表示已保存的示教片段 并不是已标定或可直接运动的机器人轨迹

恢复必须重新检查关节顺序 机械臂与 URDF 指纹 有限数值与关节限位

加载历史记录不会让机械臂运动 回放必须单独确认并通过起点及故障校验

GUI 的历史记录选择独立于实时标定事件 不会因新的 FAULT 被自动覆盖

可通过扫描已有任务与重新检查记录读取磁盘上的最新状态

## 停放

Tomato-Picker 自带 `config/serialarm/core.yaml` 的停放速度比例改为 `0.10`

原值 `0.05` 会把已缩放的关节命令速度再降到 5% 导致较长的返回时间

柔性接近阶段最多使用前 40% 的停放时间 随后提前切换刚性跟踪做精确收敛

停放速度仍受 URDF 速度约束 `cmd_vel_scale` 与加速度限制约束

停放必须满足位置误差 速度阈值和连续稳定时间才允许失能

如果反馈缺失或停放超时则保持并停止失能 不会强制关闭驱动

需要注意实际机器人的零位 线缆与碰撞空间 无环境避障规划的停放轨迹仍须人工确认空间安全

本次没有放宽关节限位 或者使能 FAULT 时自动运动

## 验证

Launcher 与 Python 测试覆盖历史记录读取 缓存失效 检查点选择和安全逻辑

提供独立 C++ DT 看门狗检查 但仍须在完整构建环境运行 `colcon test`

真机需从低风险初始位姿开始验证停放与控制周期行为
