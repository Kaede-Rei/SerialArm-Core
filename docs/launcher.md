# 串联机械臂工作台

工作台用于配置串联机械臂、检查模型、控制运动、示教回放与标定；模型与控制配置由 Profile 管理，硬件通过对应驱动接入

## 打开与选择机械臂

```bash
./install.sh
./launch.sh
```

Core、模型查看、标定和桌面控制独立于 ROS2；已有 Core 时可用 `./install.sh --gui-only --yes` 补装 GUI，环境要求见 [安装](install.md)

![机械臂工作区](images/launcher-start.png)

从机械臂列表继续使用已有配置；“打开机械臂 Profile”扫描资源目录，“选择机械臂 Profile 文件 · YAML”直接指定配置文件，“新建机械臂 Profile”从 URDF、Xacro 或 Description 包创建配置

Profile 保存模型、关节映射、控制参数与硬件资源引用；外部机械臂的资源由自己的项目维护

串口、波特率、Bus 和资源搜索路径可以覆盖本次连接，留空使用 Profile 默认值；多个资源目录用冒号分隔

## 检查配置与连接

机械臂准备页面分开显示配置、运行、标定与记录

| 区域 | 检查内容 | 使用方式 |
| --- | --- | --- |
| 连接前配置 | 模型、关节映射、驱动、控制与安全参数 | 按具体待办跳转配置字段，保存后返回检查 |
| 运行检查 | 连接后的反馈、执行器状态与当前故障 | 连接工作台后查看，异常时按故障原因处理 |
| 基础标定 | 重力补偿验证 → 执行器增益自动标定 | 先验证补偿，再生成并验收执行增益 |
| 专项标定 | 重力模型校正、高级动力学辨识、几何标定 | 按模型与应用需要选择 |
| 检查记录 | 操作者备注、已导入的验证结果 | 对照配置与记录来源，配置变化后重新核对 |

离线会话检查模型与必要 Core 参数，实机连接另检查驱动和硬件映射，基础标定再检查写入、拖拽阻尼与重力补偿；准备页按缺项定位字段

关闭写入时使用 mock，会话可在没有电机型号和硬件插件的情况下运行；实机使用前核对硬件、开放写入并重新连接，检查真实反馈后再使能

各检查卡片提供“记录自查结果”或“查看或更新自查”；完整记录显示“已自查”，未完成的记录显示“部分自查”，配置依赖变化后显示“相关参数已变化”

模型解析、配置有效性、当前反馈与人工自查分别显示；自查记录用于留档，实机连接按当前模型、驱动、硬件与写入条件判断，无需用自查记录换取连接许可

“运动与停放”进入控制页的机械臂运行区，检查使能、保持与停放；专项标定通过同级卡片进入对应工具

连接前核对电机 ID、方向、零位和限位；开启 `write_enabled` 后程序才会向真实执行器写入命令，启动确认不会修改这个开关

## 参数配置

![参数配置](images/launcher-profile.png)

参数按模型、关节映射、运动与交互、安全、停放、硬件与总线组织；点击待办定位具体字段并短暂高亮，完成后保存并返回检查

硬件页选择并检查与执行器匹配的驱动，再导入对应 Hardware YAML；导入先更新草稿，保存后写入当前配置；缺少驱动时安装对应组件或指定共享库路径

达妙驱动提供内置硬件字段初始化，填写电机型号、ID 与总线参数后核对映射；其他驱动使用各自的 Hardware YAML

模型导入使用独立 Xacro 依赖，支持从项目资源中解析 `$(find package)`；创建 Profile 时收拢网格资源与外部网格包，必要限位和资源错误会定位到 URDF

运动与交互配置分为三部分

- 默认控制方式：原生阻抗或模型导纳
- 执行器增益：刚性、柔性、拖拽、伺服跟踪；刚性与柔性的保持和跟踪数值分别保存
- 模型导纳：外力观测、交互响应目标、M/D/K 和退让限制

默认跟踪用途由 `control.runtime.tracking_gain_profile` 选择刚性、柔性或伺服跟踪；旧配置缺少此字段时沿用 `tracking_impedance_mode` 推导的用途

新建、保存和导出使用四用途配置：`control.controller` 下包含同级的 `allow_full_cmd`、`rigid`、`compliant`、`drag` 和 `servo_tracking`。刚性与柔性各有 `hold`、`tracking` 两套逐关节 Kp/Kd 任务参数，拖拽与伺服跟踪直接保存 Kp/Kd；保持与跟踪不是额外用途

刚性保持补偿在 `control.hold_compensation` 中配置，只作用于原生阻抗下的刚性保持

配置编辑器修改的是保存值；连接覆盖、会话调参和标定试用值分别显示，保存前检查目标文件与差异；输入错误会保留在原字段，切换分组后仍可修正

确认放弃修改后，返回参数页会重新读取磁盘配置；取消离开或目标页面加载失败时保留草稿

## 模型查看

模型查看读取 Core 加载的 URDF 与动力学结果，显示机器人结构、关节轴、坐标系、质心与惯性

所有三维预览统一使用左键旋转、右键或 Shift 平移、滚轮缩放；鼠标位于预览画布内时，滚轮只缩放模型，画布外仍滚动页面

![模型与控制视图](images/launcher-light.png)

可单独切换 Visual、Collision、Link Frame、Joint Axis、Labels 和惯性图形；选中对象后可查看其参数并高亮显示

关节滑条与数值框编辑同一组预览姿态；模型预览不发送执行器命令

URDF 中的连杆惯性与 Core 约简后的有效惯性分别展示，无效参数对应的惯性图形不可用

### 三维兼容与恢复

默认使用正常 GPU 三维；模型查看、控制、示教回放和标定共用同一套 Three.js 场景

遇到 `THREE.WebGLRenderer: Error creating WebGL context.` 或运行中图形上下文丢失时，错误显示在预览区域；可在原位查看详情、重试、打开图形诊断或选择兼容三维，机器人连接、模型解析和运动状态分别显示

模型网格缺失、读取失败或无法解析时，预览区域列出连杆、资源与原因，图形诊断单独显示模型加载状态；渲染器已创建不等于模型已完整加载。“重新加载模型”会重新读取模型和资源，并保留可恢复的视角、图层与选择；恢复完整预览前，需要目标或路径预览的执行确认保持不可用

图形诊断也可从设置打开，按状态概览、最近一次三维预览、显卡与驱动、运行库和日志分组展示；图形功能、启动参数与历史记录可展开查看，尚无预览记录时会明确提示；导出 JSON 保留完整数据，可用于核对报错机器的环境，不需要连接机械臂

设置中的“三维渲染”提供三种带用途说明的选项：正常 GPU 三维用于日常预览，兼容三维用于显卡预览异常，无三维救援关闭预览并保留数值操作；选中项显示勾选，“当前使用”显示实际生效模式，需要重启时另列待生效模式和手动重启按钮

兼容三维使用 Electron 自带的 ANGLE SwiftShader 软件后端，保留模型旋转、关节姿态、目标虚影、轨迹、坐标系、质心和惯性展示；软件绘制会增加 CPU 占用，因此降低像素密度与刷新频率，静止和窗口不可见时减少或暂停绘制，原生控制周期不变

该后端需要 Chromium 的 `enable-unsafe-swiftshader` 选项，会降低软件 WebGL 在 GPU 进程中的安全保证，Renderer 沙箱仍启用；应用内切换时会说明影响并要求用户主动同意，不会因 GPU 初始化失败而静默开启

切换图形后端需要重启应用；有运行会话时先保留当前窗口，由用户结束会话后再切换，模式切换不会自动停止、停放或重启机械臂；同一模型重试时保留可恢复的视角、图层及预览选择

正常与兼容三维均不可用时可选择无三维救援模式，继续配置、查看数值状态、管理记录和导出；预览区域标明三维不可用并保留恢复入口，依赖姿态预览的目标移动与回放确认受限，跳过预览不会记为检查通过

本机正常 GPU 与兼容软件后端的绘制检查用于验证这两条路径；其他机器的具体显卡或驱动故障仍需结合其导出的诊断确认

## 控制工作台

控制工作台、几何标定、动力学标定、连接与诊断、启动适配层页面显示同一张顶部固定状态卡，并位于模式选择上方。模型查看、机械臂准备状态和参数配置页面不显示此卡。第一行显示绿点 `ACTIVE` 或红点及实际状态；未连接、未使能和故障分别保留 `OFFLINE`、`INACTIVE`、`FAULT`，不混为一类

第二行分为两组：使能、停放并失能、立即失能；当前位置刚性保持、柔性恢复、清除故障。窄窗口按组换行，按钮是否可用由实时状态决定。页面内不再重复放置这些通用按钮，运行中的居中任务窗保留专属保持、取消和失能入口

“当前位置刚性保持”捕获当前实测位置并选择刚性保持；原生阻抗使用刚性增益，模型导纳使用其要求的伺服跟踪增益，不切换已选控制方式。普通任务保持仍沿用原有用途语义

| 页面 | 用途 |
| --- | --- |
| 控制 | 使能、停放、保持、控制方式、增益用途与关节目标 |
| 示教回放 | 记录、保存、导入轨迹与设置回放 |
| 交互调试 | 调整本会话交互响应，记录并分析受扰响应 |
| 运行监视 | 查看反馈、参考链路、外力估计、命令力矩与限制原因 |

### 控制

先连接工作台，在反馈正常且无故障时使能；任务状态显示保持、移动或拖拽，增益用途显示刚性、柔性、拖拽或伺服跟踪

原生阻抗按名义目标执行，使用所选用途的执行器增益；模型导纳根据外力估计产生退让参考，统一使用伺服跟踪增益跟随该参考

控制方式与原生模型前馈在失能状态切换；工作台普通示教临时使用原生阻抗与重力补偿，结束后恢复原控制上下文

关节目标只保留一组滑条和精确数值框，拖动时青绿色半透明模型连续显示目标姿态；编辑后点击“移动到目标”才发送运动命令

“控制参数”默认展开，可查看和修改控制方式、执行器增益用途与模型前馈；手动收起后，当前工作区保留该选择

速度比例须在 `(0, 1]`，清空、零值和越界值会阻止移动；命令提交后显示执行状态，参考结束且新鲜反馈持续满足逐轴位置与速度容差后显示完成

目标编辑显示当前有效位置范围；旋转关节的显示单位可选 rad 或 °，直线关节可选 m 或 mm，提交给 Core 的数值按 rad 或 m 转换

“同步实际”把当前反馈作为新目标；目标归零只修改预览；“当前位置保持”停止当前移动并捕获当前位置作为保持目标

普通模式交接保留原名义目标，避免把受扰偏移当成新的保持位置

### 示教回放

1. 连接并使能，开始示教后进入拖拽
2. 在安全范围内拖动机械臂，结束记录后检查轨迹
3. 命名并保存，或从轨迹管理中导入已有轨迹
4. 选择已保存轨迹，连接后点击“载入所选轨迹到当前会话”
5. 选择单程正放、单程倒放或往返；往返模式再设置次数，并选择速度、控制方式与增益用途
6. 核对青绿色起点预览，松手并确认路径后开始回放

正放从记录首点到末点，倒放从末点到首点，都只运行一个单程；往返 N 次执行 2N 个单程，起点预览随方向更新

选择轨迹后，可拖动时间轴逐帧查看整段记录，青绿色虚影显示当前预览姿态；“载入所选轨迹到当前会话”单独加载执行数据

“将所选起点填入目标草稿”切到控制页，预览后点击“移动到目标”；预览与草稿编辑均不发送运动命令

开始前显示各关节相对所选端点的误差；检查虚影并移动后，回到回放页再次核对；回放速度比例须在 `[0.05, 1]`，无效输入直接指出错误，不沿用旧值

普通回放的直线关节起点允许位置误差 1 mm、速度 1 mm/s；触点往返收紧为 0.5 mm、1 mm/s；旋转关节分别按 0.08 rad / 0.05 rad/s 和 0.03 rad / 0.03 rad/s 检查

模型导纳回放使用伺服跟踪增益；原生阻抗回放可使用刚性、柔性或伺服跟踪，拖拽用途不用于轨迹回放

示教轨迹按机械臂保存在 `.serialarm/teach-replay/`，支持 ZIP 导入导出、重命名和删除；选择与管理已有轨迹无需连接，载入实机会话前检查当前配置并确认；故障中断的录制显示失败原因

模型、关节顺序、执行器映射或坐标系变化后，旧轨迹继续作为历史记录展示并可导出；回放要求与当前配置匹配，预览可用性另行显示

### 交互调试

选择模型导纳后，可用“受扰后回位”或“自由移动，松手减速”生成所选关节的参数草稿；专家视图可直接编辑 M/D/K

响应时间是虚拟模型指标，实际效果通过响应记录检查；`K=0` 时松手后减速，不拉回原位置

应用只影响当前会话，运行中的参数按控制周期平滑过渡；保存为默认值需要单独预览差异并确认

响应记录包含名义参考、导纳参考、最终参考与实测运动；记录期间保持执行器增益和控制方式一致，切换用途或增益前先结束当前记录；标记松手时刻后，可检查原目标、关节回位与外部针尖测量

关节反馈用于关节回位判定；针尖精度需录入独立外部测量，缺少测量时显示未验证

### 运行监视与故障处理

监视页显示关节与执行器反馈、反馈年龄、加速度有效性、观测器状态、逐级参考、力矩预算与限幅原因

故障弹窗显示原因和当前处理结果，错误码与完整诊断可展开或复制；关闭弹窗保留故障状态

停放会沿配置路径回到停放姿态后失能；立即失能直接撤去驱动，操作前需可靠支撑可能下落的机械臂

通信超时后先检查硬件和当前运动状态，执行结果未知的运动命令不要直接重复发送

## 基础标定与专项标定

准备页将标定分成两组：基础标定按“重力补偿验证 → 执行器增益自动标定”进行；专项标定包含重力模型校正、高级动力学辨识与几何标定，按当前需要进入

重力补偿验证用于比较补偿比例和受控拖拽表现；发现模型问题时进入重力模型校正，再验证新结果

## 动力学标定

![动力学标定](images/launcher-dynamics.png)

各工具共享任务记录，按机器人、工具与搜索条件筛选后分页；离线重算的不同轮次可分别选择和比较，预览、保存与导出始终显示所选来源和轮次

### 执行器增益自动标定

导入检查过的示教轨迹，选择刚性、柔性、拖拽、伺服跟踪或全部用途。确认起点、负载、线缆与整条回放路径后，完全松手并开始自动标定

自动阶段预算为最初有效录制时长的 12 倍，包含候选调整和独立测量；例如 25 秒轨迹对应约 300 秒。示教录制与手动起点对齐不计入自动阶段。导入任务保留原始时长与来源任务，多次导入或安全重定时不会累加预算。规划另用安全重定时后的实际单程时长计算每趟成本，柔性回放按 65% 速度单独计算；开始前显示原始时长、预算、预计用时和整轨趟数上限。预算可能不足时提示本次只能完成部分测量，仍允许启动，不通过额外提速压缩时间

参考指标用于评价结果，不作为应用和导出的硬门槛。完成测量但未达 RMS、峰值、稳定时间或刚柔分离等指标时，任务正常结束并显示警告；这些用途仍可选择、应用、保存和导出。`validated` 保留指标是否达标，`available` 表示是否已有可用测量结果，`warnings` 保存提示。未开始或被故障中断的测量显示“未测”或“未完成”，不伪装成指标通过

| 用途 | 独立验收 |
| --- | --- |
| 刚性 | 固定候选后的整轨跟踪与定位保持；采用保持补偿时另测补偿效果 |
| 柔性 | 相对刚性参考的增益边界、65% 速度整轨跟踪与定位保持 |
| 拖拽 | 全轴局部运动后释放，分别测量各轴的真实初速度、衰减与稳定性 |
| 伺服跟踪 | 固定候选后的整轨原生跟踪；配置启用模型导纳时增加导纳轨迹验收 |

跟踪阶段沿整条示教路径往返，所有关节同时采样，不再逐关节运行多轮小正弦探测。每趟从上一趟结束端继续，回放前检查端点、静止速度和新鲜反馈；位置不匹配时要求手动对齐，不自动跳回起点

1. 等待控制切换回稳，再从滚动窗口同时采集各轴噪声与编码分辨率
2. 沿示教轨迹联合测量，按未合格轴的实测误差调整有界候选
3. 固定候选，使用新的一趟数据独立验收；柔性用途另测对应参数
4. 验证定位保持，并进行全轴联合拖拽释放与独立复测

启动采样先避开控制交接，再有界等待稳定窗口。窗口内尚在回稳时重新取样；等待到限仍未完全静止时，保留警告和实测编码分辨率后继续，不把漂移幅度当成噪声来抬高后续门槛。没有新鲜反馈或控制故障仍中止执行

候选调整仅修改有足够运动数据的轴。首帧位置偏差、真实往返行程与跟踪精度分开记录；RMS、峰值、超调、尾部稳定性、响应可测性和非故障限幅结果用于评价及提示，不因单项未达参考值而拒绝完整测量的增益

尾部振荡根据连续实测位置是否反复越过编码分辨率与噪声门槛判断；位置已回稳时，原始速度码的正负跳变不再触发降刚度。定位保持和拖拽衰减按位置变化判断运动，原始速度峰值单独保留为诊断。实际漂移或振荡记录为质量警告；原生 Safety 的位置、速度、力矩限制及故障处理不变

USB2CAN 按同一电机端点的接收间隔检查反馈连续性，避免把不同电机正常紧邻到达的报文误判为异常。同一端点的突发重复报文、长间断、首次接收和队列溢出仍标记时序无效；反馈时间戳及原生控制周期不变。保持补偿另记录观测器可用样本、积分有效样本和失败原因；补偿复测结果保留用于诊断，只有实际采用并启用的补偿才能参与用途验收

整轨测量不等同于扫频辨识。本次结果记录为 `independent_demonstration_trajectory`，列出示教路径上的实际误差与控制条件，不生成未经测量的截止频率、极点或导纳带宽边界；旧局部多频记录保留原有范围

额外拖拽测试在回放结束后的当前姿态附近进行，每轴最大局部偏移为 `0.04 rad`（约 `2.29°`），还受位置、速度、加速度与力矩限制约束。全轴使用有界跟踪参考建立运动，再同时切换到零 Kp 的拖拽增益；每轴都须测得有效释放速度，并独立检查衰减，未运动的轴不计为通过

拖拽衰减按连续位置变化和测得的编码分辨率判断，单个原始速度码尖峰不当作持续运动。原始速度峰值、位置速度、释放初速、末速与衰减时间分别记录；真实持续漂移、速度增加、振荡和反馈中断仍不能通过。安全速度限制按原配置执行

自动采集与回放统一使用居中标定卡，覆盖增益标定、重力与摩擦采集、几何自动往返测试。卡内显示三维预览、各关节当前值、目标值与差值；增益流程另列用途、整轨趟数、候选轮次、已用时间与剩余预算。三维预览复用原场景，实体机械臂跟随实际反馈，青绿色半透明虚影显示当前参考；与实测姿态重合时仍显示轮廓。保持、取消与立即失能始终可用；增益测量被保持中断时保存部分结果，重新标定需再次确认路径

手动示教、重力补偿验证与固定点几何采样保留原页操作。导入轨迹后的引导对齐在同一张卡中显示逐轴当前值、目标值、差值与门槛；反馈过期时保留目标，当前值与差值显示不可用，不能开始自动回放

到达本次按原始时长计算的时限后停止后续测量并进入保持，正常保存已采集数据和各用途结果，同时提示预算已用完。已完成的用途包括未达参考指标的用途，均可单独查看、临时应用或导出；未完成的用途保留未测状态

诊断列出各轴实际增益与安全上限、窗初偏差、同向正反行程和未通过项目。尾部峰值与稳定误差阈值分别显示，是否稳定按收敛时间和持续稳定条件判定。任务导出包含整轨、静止采样与拖拽衰减 CSV

搜索不再把误差超标倍数直接换成 Kp 倍增。示教路径中的偏置、幅值不足和速度相关偏差分别记录；候选小步调整 P/D，只有实际测量更合适时才保留，否则退回已测参数。最后独立测量使用一整组已测过的增益，不拼接未共同测量的逐轴参数；Safety 上限只作边界

刚性、柔性的保持参数分别沿用并测量当前配置，不被跟踪候选覆盖；候选页分别显示跟踪与保持 Kp/Kd，采用和导出保存对应的实测参数

每趟结束后继续保持示教端点，等待增益交接后的新鲜位置反馈回稳；窗口显示各轴目标、当前值、偏差、速度与反馈年龄。最长等待 2 秒，并计入原始轨迹时长 ×12 的总预算；到时仍需对齐则保留已测用途并提示，后续回放不开始。反馈中断、无效数值和 Safety 故障仍按执行故障处理

候选页按用途显示达标、警告和未测状态，并列出逐轴跟踪误差、参考指标、保持结果与对应 CSV。执行故障才进入错误窗口；末次拖拽结果不覆盖其他用途的证据。结果尚在读取或文件缺失时明确显示状态，不借用另一任务的记录

临时应用只影响当前会话；保存或导出按勾选用途写入跟踪、保持及实际采用的补偿状态。柔性候选保留测量时的刚性参考，与本次采用的刚性增益不同会提示；指标警告不禁用操作，也不增加确认弹窗。模型与关节映射、有限值、参数维度、Core 安全上限及切换时的失能要求仍按原规则检查

导入带质量警告的增益记录后，合法参数仍可用于使能、移动、示教和停放。临时应用历史候选前会核对标定时的映射、模型、补偿、控制频率和硬件条件；配置已变化时不能沿用旧测量条件直接应用。导出仅在上下文可确认一致时合并当前配置，否则根据任务快照与实测控制上下文生成配置，并在提示及包内 `README.txt` 中说明来源和差异

刚性基线完成后，可选保持补偿复测的超时或失败不会删除已完成的基线结果；只提供实际完成测量的增益和补偿状态。重复或滞后的启动请求被拒绝时，不改变正在运行的标定用途和参数

更换路径或负载后，可应用候选并在“交互调试”中记录普通示教回放，返回候选页做补充路径验收。记录至少需要 2 秒和 100 个有效样本，期间模型、增益与控制方式保持一致；报告范围为本次记录的参考路径和条件

旧平铺六组增益及 `identification_tracking` 只兼容读取；新旧字段对应同一任务时，等值可读取，冲突拒绝。新式配置必须完整提供四组及刚性、柔性的 `hold`、`tracking`，缺项时定位到对应字段；保存或导出统一写四用途结构。旧候选仍按原记录要求检查，不因配置布局变化而自动升级验收资格

旧 GUI 生成的 YAML 锚点和共享别名可自动展开为四用途配置；转换保留控制器以外的配置值，包括共用增益的故障恢复参数，无需先手动整理 YAML

### 重力模型校正

1. 拖动示教一条覆盖所需姿态的安全路径
2. 结束后检查训练与留出姿态分配
3. 完全松手，确认双向静态与多速度自动采集
4. 保存任务，比较基线与候选的训练和留出误差
5. 审核后临时应用或导出，使用独立会话验证

自动阶段可以暂停、继续、取消、保持或立即失能；暂停后位置变化过大时，继续需要重新确认

旧版单项静态标定、摩擦录制与摩擦回放也可直接保持或立即失能；立即失能先执行执行器失能，再回收任务线程

摩擦双向回放前须有三维预览，并将机械臂停在示教末点；原生端在启动及每个单程前检查端点、静止速度与 150 ms 内的新鲜反馈，条件不符时拒绝回放，不自动移动对齐

在线预览固定质量及质心处惯量，只校正静态重力相关的一阶矩；离线静态重算可同时辨识质量与一阶矩，并按该轮次保存到重力校正文件；运行时重力覆盖不替换质量矩阵与科氏项，不能配合 `FULL_INVERSE_DYNAMICS` 或 `FULL_ID` 使用

候选应用与恢复在失能且无活动模型任务时执行；保存写入独立校正文件和 `gravity_correction_path`，保留校正前备份

模型动力学参数、控制链、映射、重力向量、补偿比例或校正内容变化时，保存会撤销 `gravity_model_validated`；预览和结果显示撤销原因，故障柔性恢复需在当前机械臂与负载下重新核对，再到安全策略确认；只改增益或把相同模型内容换到另一路径时保留确认，恢复旧备份不会恢复过期确认

任务目录保存 `metadata.json`、`frames.csv`、`trajectory.csv`、`result.json` 与源快照；新任务另存硬件原始配置、生效配置及本次连接覆盖，历史记录按条件搜索与分页，不被其他工具任务挤出列表

静态验证通过表示达到当前误差容差；`prior_preferred=true` 或保留先验表示本轮未支持更新参数

### 高级动力学辨识

按“数据检查 → 辨识设置 → 结果与推荐 → 导出”操作，可选择静态重力或完整惯性辨识、全局或局部范围；局部模式中勾选的可信连杆从求解开始保持固定

离线处理使用已保存任务；拟合、重算和采集审计前断开运行会话，已保存记录、候选和成果的普通导出可在连接期间后台完成，保持与失能命令继续响应

报告与候选 URDF 应保存在同一目录；新报告保存候选相对路径，搬迁旧报告时优先读取报告目录中的同名候选，应用和导出继续核对原有内容与模型来源

原始与去偏置误差分别展示，模型改善按实际导出的原始预测判定；算法、导出条件及实验案例见 [离线重力辨识](reference/offline-gravity.md) 与 [完整动力学辨识](reference/dynamic-identification.md)

## 几何标定

固定点工具分为临时针尖的 FK 一致性诊断和 TCP 位置候选；采样训练姿态后，使用独立姿态验证

固定点方法辨识 TCP 平移，工具朝向沿用父 Frame；恢复实验时使用记录中的实际 Frame，临时诊断只导出报告

同一项目目录内更名 Profile YAML 后，历史实验仍按模型与映射校验恢复；迁移后的保存、导出和清除只作用于当前数据目录，原记录保留

正式 TCP 工具先预览工具 Frame、偏移和文件差异，再导出包含 URDF、Core、Hardware、Profile 与网格资源的独立成果；资源搜索与 URI 解析沿用模型预览规则；会话断开后确认采用，将候选登记为新的机械臂 Profile，原模型和配置保留

重标定已采用的 TCP 时，预览显示更新操作及采样参考坐标系；程序将相对旧 TCP 测得的偏移转换回父 Frame，并更新候选里的固定关节

重复到位测试从触点 B 记录到安全点 A，循环时从 A 倒放至 B、停留，再沿记录方向返回 A；旧的 A 到 B 轨迹需重新示教

循环与触点撤离均使用所选的控制方式和跟踪增益用途，模型导纳统一使用伺服跟踪增益

先留出接触间隙，低速核对路径，再执行接触试验；循环中可停止并保持，位于 B 附近时可沿记录路径撤离至 A

本工具不测量接触误差，也不提供自动碰撞检测；定量重复定位精度需独立测量

## Terminal、ROS2 与命令行

| 入口 | 用途 |
| --- | --- |
| `serial_arm_terminal` | 交互式 C++ 控制、调参与标定 |
| `serial_arm_terminal --machine` | GUI 使用的结构化 JSON 会话 |
| `hardware.launch.py` | 启动 ros2_control 与 Controllers |
| `moveit.launch.py` | 启动硬件、规划与 RViz |

Terminal、Python Session 与 ROS2 Adapter 复用 Core 控制运行时；GUI 启动不加载 ROS2，Hardware / MoveIt 入口按需加载已安装适配层和宿主环境；缺少环境时显示对应安装步骤，ROS2 默认跟踪用途读取 Core 的 `tracking_gain_profile`

C++ Terminal 普通示教与 GUI 使用自动临时控制上下文；Python 交互终端需显式执行“停放失能 → 原生阻抗 → GRAVITY 与有效重力比例 → 使能 → 拖拽”，结束后由用户在失能状态切回原控制方式

终端使用 PTY，Ctrl+Shift+C 复制、Ctrl+Shift+V 粘贴，Ctrl+C 中断程序；运行中连接参数固定

GUI 按实际设备路径互斥占用，直接运行底层程序需自行保证设备独占

正常断开等待停放与失能，停放失败会保留连接并显示原因；强制结束会中断清理，需现场确认执行器状态

后台进程已退出而会话状态未更新时，关闭窗口仍先要求确认硬件已可靠支撑、必要时急停或断电；确认后仅清理本次启动的已知进程并退出，不再向失联后台发送停止请求，也不将本地进程退出记为电机已失能

保存后的模型任务也可用 CLI 处理

```bash
source .install/setup.bash
PYTHON="$PWD/.install/gui-venv/bin/python"
CORE=/path/to/core.yaml
TASK=/path/to/task
"$PYTHON" tools/model_calibration_cli.py inspect --directory "$TASK"
RESULT="$("$PYTHON" tools/model_calibration_cli.py recompute --config "$CORE" --directory "$TASK")"
RUN_ID="$(printf '%s' "$RESULT" | "$PYTHON" -c 'import json,sys; print(json.load(sys.stdin)["candidate_run_id"])')"
"$PYTHON" tools/model_calibration_cli.py preview-save --config "$CORE" --directory "$TASK" --source offline --run-id "$RUN_ID"
"$PYTHON" tools/model_calibration_cli.py save --config "$CORE" --directory "$TASK" --source offline --run-id "$RUN_ID" --confirm
"$PYTHON" tools/model_calibration_cli.py export-urdf --config "$CORE" --directory "$TASK" --source offline --run-id "$RUN_ID"
"$PYTHON" tools/model_calibration_cli.py restore-config --config "$CORE" --directory "$TASK" --confirm
```

`--candidate-path` 可替代 `--run-id` 选择当前任务内归档候选，两者互斥；在线结果使用 `--source online`，任务存在离线候选而未指定来源时拒绝保存与导出，避免混用旧结果

旧记录按 Profile 归属复制到新位置，原文件不删除；同 ID、同内容的轨迹去重，内容不同的冲突轨迹使用独立 ID 并保留来源，加载和删除各自生效；自查记录按归属与配置依赖合并，无法确认归属的文件留在原位置；删除已迁移的轨迹后不会再次自动导入

./.install/run ros2 topic echo /joint_states --once

`/recognize_objects not available` 表示物体识别 action 服务未启动，检查对应服务
