# 动力学标定与候选 URDF

## 在线流程

拖动示教 → 轨迹重新计时并预估 → 松手确认 → 反向回放（选定静态姿态停稳采样，同时记录运动数据）→ 重力拟合及留出验证 → 正向回放（运动数据）→ 摩擦参数交叉验证 → 保存记录

- 任务默认采用一次往返，不再固定执行六趟，预计全流程：`示教时间 + 2 × 规划单程时间 + 1.5 × 姿态组数 + 2 s`，这是在线标定的标称值，不包含后续完整惯量离线导出与验证；停稳、暂停、硬件故障会延长时间
- 150～200 s 是目标，不是固定限制，也不是质量或安全保证，超过目标不会放宽关节速度/加速度，不强制结束运动
- 轨迹仍通过现有连续速度的 Hermite 插值执行，静态姿态采样需要停稳，实际视觉上会有有意的停顿；这不是完全不停顿的圆滑运动
- 一次往返比六次采样更省时，但摩擦拟合需要速度正负两向及足够速度跨度，如果 `friction_pass=false`，**不得当成已辨识或启用摩擦补偿**
- 记录、候选生成与硬件运动是不同阶段，自动任务完成不代表完整惯性参数已经可辨识

## 候选 URDF

| 导出方式 | 能修改的参数 | 质量门槛 |
| --- | --- | --- |
| 原有重力候选 | 仅 Link 质心坐标（质量和惯性张量保留 URDF 值） | 无偏移硬门槛，拟合质量及留出验证结果供人工审核 |
| 完整惯量候选（实验） | 可动 Link 的质量、质心与质心处惯性张量，未能唯一映射的 Link 不修改 | 双向有效运动数据与参数映射检查，回归秩、物理一致性、质量和质心偏移、留出 RMS 作为审核诊断，不设自动批准门槛 |

完整惯量候选使用 Python Pinocchio 的 `computeJointTorqueRegressor()` 和 NumPy，需要在 Launcher 的 Python 环境中具备 `import pinocchio, numpy` 的能力，缺依赖会直接解释，**不会自动下载安装系统依赖**

即使导出成功，若 `all_parameters_identifiable=false`，说明只得到了受 CAD 先验约束的候选值，**不能表述为每个 Link 的全部 10 个参数均已独立辨识**，当回归秩不足、物理一致性不佳或留出集效果下降时，仍保留可表示为 URDF 的数值候选并显示审核警告，无法形成有效结构或非有限参数时才拒绝写出

候选生成仅写到用户选择的目录，不会自动安装到 Profile、控制器或替换已有 URDF，使用前必须人工复核关节力矩反馈方向、传感器噪声、无外部接触假设，并完成独立静态及动态验证

## 验收前检查

1. 备份 Profile、URDF、`.install/model-calibration` 原始数据，重新编译 C++ Core
2. 用短轨迹检查反向静态停留和正向回放过程，确认无突然加速、碰撞、线缆牵拉
3. 记录 GUI 的规划单程和任务预估时间，真实时间以真机日志为准
4. 检查静态 holdout、摩擦 `friction_pass`、完整惯性报告里的数值秩及留出集 RMS
5. 独立测试候选 URDF 的静态广义力、动态力矩预测与自碰撞安全，再考虑手动应用


## 加载、恢复及重试任务

- 在工作台「标定」页选择「加载任务记录」，选中整个 `model-calibration-*` 文件夹，仅查看记录不会触发机械臂运动
- **仅示教**：存在 `metadata.json` 和完整 `trajectory.csv`，即使没有 `result.json` 也可以显示原轨迹，并在工作台连接、机器人处于 ACTIVE、无其他运行中的标定时点击「恢复轨迹到当前会话（不运动）」
- **已中断**：若保存了完整轨迹，可以复用轨迹重新开始采集；并不支持从已经走到一半的关节运动或采集阶段继续，若缺少 `trajectory.csv`，任务只允许查看，不允许恢复运动
- **已完成**：可加载原 `result.json` 并使用原有校正结果处理工具，也可以选择重新从原轨迹采集，实验性完整惯量候选仍需单独验证
- 每次恢复先检查核心配置和 URDF 指纹、Profile、关节顺序、完整轨迹及保护边界，并按当前速度和加速度约束重新规划，不同版本、模型、硬件参数不兼容时会拒绝恢复
- 恢复后会在 `.install/model-calibration` 创建**新的任务目录**，保留旧任务的 `metadata.json`、`frames.csv`、`trajectory.csv` 和 `result.json`，新任务中的 `imported-from.txt` 记录来源
- **严禁直接从停放姿态跳转到轨迹起点**：反向回放从原示教末端开始，操作者须手动安全地将机械臂调整到记录末端姿态，使最大关节位置误差不超过 0.08 rad、最大关节速度不超过 0.05 rad/s，然后单独确认回放；否则 Core 会拒绝启动，不自动归位，也不会自动清除 FAULT
- 从历史轨迹开始的新任务，其时间预估**不包含原示教的耗时**，在线采集仍按双程规划与静态采样估算；该估算不是时间/标定精度保证
- 修改 C++ Core 后必须重新编译安装；仅重新启动 Launcher 不会更新原生导入接口


## 历史轨迹回放起点（安全恢复）

- 恢复记录只复制数据，不执行电机运动；读取时从原示教起点/终点中选择与当前真机姿态更接近的一端，若选择原示教起点，会翻转导入后的轨迹存储顺序，核心依然先反向、再正向采集，实际执行的是原来录制的几何轨迹，不插入从停放位到示教点的直达轨迹
- GUI 显示六关节实际位置、目标位置和误差，实时校验 **|Δq|max ≤ 0.08 rad、|dq|max ≤ 0.05 rad/s、反馈不超过 500 ms**，Core 在确认动作时再次独立检查，GUI 不可绕过
- 若距离两端都较远，可按“引导返回回放起点（人工拖拽）”，确认机械臂已被物理支撑后进入 `COMPLIANT_DRAG`；操作员手动缓慢调整，再按“结束引导并保持当前位置”切换到 `RIGID_HOLD`，对齐后另行确认自动回放
- **不提供从停放位到示教点的自动关节插补归位**：Standalone Core 当前没有规划场景与环境碰撞检测能力，直接从零位到目标的插补有碰撞风险，未来接入 MoveIt/规划场景时可再提供经过碰撞验证的自动归位
- 如果已经停放并失能，必须按原安全流程重新使能；进入拖拽前确认机械臂的负载、重力补偿和环境风险，FAULT、超时、速度不满足门槛都必须先人工排查

## 候选 URDF：无质心偏移硬上限与人工审核

- 重力候选采用按姿态去除关节常量偏置的稳健 SVD 岭回归，包含迭代 Huber 异常采样降权，数值秩不足的方向保留 URDF 先验，**不使用 COM 偏移硬上限，也不再把 COM 偏移大小用于回归器的数值尺度**
- `static_pass`、留出集 RMS、数值秩与 `com_offsets_m` 是**审核诊断**，非 URDF 文件生成的门槛，任何有限且格式正确的候选均可导出供人工审核；未通过留出验证的候选不允许自动应用到在线控制器
- 旧任务可通过“加载任务记录 → 离线重算 → 导出候选 URDF”，读取 `recomputed-candidate.json` 中的新拟合结果；无需重新拖拽示教，原始 `result.json`、URDF 保持不变
- 重力候选目前**仅修正固定质量下的质心**（保留原 URDF 的质量与惯性矩），不等于所有 inertial 字段辨识；完整惯量候选通过另一个独立的实验性离线导出入口生成，返回物理有效性与可辨识性警告而非自动审批
- 任何候选均不得在未人工审核和真机安全验证前直接作为控制模型；`candidate.urdf` 和 `candidate-inertial.urdf` 都不会覆盖源 URDF
- 没有 `<inertial>` 的 `tool0` 等工具坐标系不会被强行创建质量属性，重力候选保留其原始 XML，并在报告中列出跳过的 Link
- 完整惯量实验候选只反写与标定 CSV 对应的可动关节 Link，未采集的辅助关节保留原始惯量，并在计算中假定其处于 URDF 中立位姿
- 若附属关节在录制期间实际运动，或固定附属 Link 含不可分离的非零惯量，该辨识结果不具备完整的物理可辨识性，不能视为验证通过或直接部署


## 候选导出异常处理

- 历史任务记录的 URDF 指纹采用 C++ FNV 64 位格式，离线重力候选首先验证任务快照 `source/model.urdf`，而不是直接要求旧绝对路径仍可读取
- 旧的 SHA-256 格式记录也支持只读校验，指纹不匹配时会明确报错，不会为了生成候选而改写记录元数据
- 重力候选导出与候选验证分开执行，验证失败返回审核警告，不会导致 Launcher Backend 退出
- 完整惯量候选在独立 Python 子进程中调用 Pinocchio，避免可选二进制模块崩溃导致整个 GUI 后端失效
- GUI 安装流程在独立 `gui-venv` 中安装 `numpy<2`，兼容 ROS Humble 环境中以 NumPy 1.x ABI 编译的 Pinocchio 扩展
- 若子进程仍遇到 NumPy ABI 错误或段错误，Launcher 会展示明确错误并保持其他操作入口可用，未验证的惯量候选不会自动应用到真机
