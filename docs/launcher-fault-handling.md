# Launcher 故障与标定处理

## 速度限位：URDF 不等于实际生效阈值

- `URDF /limit velocity` 是基础速度约束（rad/s）
- `safety_policy.cmd_vel_scale` 是命令速度比例，命令速度上限 = URDF velocity × cmd_vel_scale
- `safety_policy.state_vel_scale` 是实测速度安全倍率，状态速度故障阈值 = URDF velocity × state_vel_scale
- 命令速度超限对应 `CMD_VEL_LIMIT`；实测速度超限对应 `JOINT_VEL_LIMIT`；应查看故障弹窗中的 `value`、`limit`、关节名称和实际生效阈值，不能仅按 URDF 判断
- 即使速度在 URDF 允许范围内，命令加速度、关节位置、反馈超时或其他故障仍可能触发安全状态

**Tomato-Picker 的配置注意事项**：`src/robot_supports/robots/tomato_picker/robot_profiles.yaml` 引用的是 `tomato_picker_description/config/serialarm/core.yaml`，该文件的 `cmd_vel_scale` 是 `0.25`，并非另一份 `config/core/tomato_picker.yaml` 中的 `1.0`，保留保守的命令限速，不要为消除报错直接提高允许速度，修改任何运行配置前必须确认当前 Profile、真机状态和路径安全

## 自动模型标定的自由示教与耗时规划

- 不再使用 `600 s` 最大自动任务时间来拒绝示教结果，示教时长不限，自动阶段仍支持主动取消；关节位置、速度、加速度、反馈与故障联锁不能关闭
- 以前使用录制的时间轴，并乘以速度倍率，六趟路径相当于 8 次单程，导致 40 秒录制、`replay_rate=0.2` 时仅回放就需要 1600 秒
- 现在保留示教的关节空间轨迹，压缩停顿及几何冗余，并用当前 Core 命令速度、加速度限制重新规划时间；重新规划的单程 `T_pass` 与人工示教墙钟时间无关
- GUI 在结束示教后展示：人工示教时长、原始记录时长、优化单程时间、自动阶段预估与包含示教的总预估，以及 `T_自动 ≈ 8 × T_pass + 3 × N_pose + 2` 秒，`T_总 ≈ T_示教 + T_自动`，最后两项是每次静止采样/停稳缓冲与计算开销的经验估计，真实收敛可能不同
- 包含人工示教在内的 200 秒是优化目标，不是新的隐藏超时：超出时在 GUI 提示实际预计值，仍可由操作者检查安全区域后选择是否回放；不会为了压缩时间突破关节限制
- 回放前必须由操作者确认松手、清空范围并确认轨迹安全，仅凭关节限位检查无法自动证明路径无自碰撞或环境碰撞

## 错误的 UI 行为

- 后台出现真实机器人 FAULT 时，GUI 立即以最高优先级弹窗通知，不需要先取消标定遮罩
- 弹窗包含真实后端 `RobotFault`、`SafetyErr`、关节名称、实际值与阈值、有效命令/状态限位；故障状态保持在 Core，不会因关闭 GUI 弹窗自动清除
- 标定失败及普通操作失败也必须显示在阻塞进度层上方；同一个故障去重，重复反馈不能无限弹窗
- 自动标定出现安全故障时停止自动运动流程；人工核对并排除原因后，按安全流程显式恢复，而不是自动继续运动

请在真实机器人周围清空工作区，确认急停装置可用，先离线验证和检查配置，再逐关节低速测试，首次真机测试应由操作人员现场监护

## 拖动示教阶段的时长与弹窗诊断

- 自由示教期间实时显示录制时间，不因录制时间太长自动结束
- 结束示教后输出 `recorded_duration_s`（原始记录时间）、`single_pass_duration_s`（优化后的单程）与 `estimated_duration_s`（自动阶段预估）及 `estimated_total_duration_s`（包含示教的全流程预估）；旧记录中的 `max_task_duration_s` 仅保留值为 0 的兼容字段
- 重放确认弹窗再次展示预估时间和简式公式；它是提示而非保证，实际执行仍可能因停稳或模型拟合失败而更慢
- 拖动示教阶段不能暂停，只能结束示教；失败时若 Robot 为 ACTIVE，会尝试切回 `RIGID_HOLD`，FAULT 状态不自动恢复
- 错误窗口使用浏览器原生 `<dialog>.showModal()` 进入 top layer；关闭错误只表示已阅读，不会自动恢复运行

## 停放失败与安全状态

停放未达到 `shutdown.position_tolerance` 和 `shutdown.velocity_tolerance` 并持续 `settle_time_s` 时，不能视为已经安全停放，Core 在超时后保持 `RIGID_HOLD`，**不执行失能**；本次增加的错误详情包含未达标关节、实际值、阈值和 `timeout_s`，方便判断是零点、摩擦、跟踪或停放目标问题，不得通过简单提高容差或自动强制失能消除错误

## 局部时间重规划修正

- 修复原实现以**全轨迹最坏样条片段**确定单一 `sample_dt` 的问题：局部尖锐转角/测量抖动会迫使所有片段一同放慢（例如 30 秒示教被规划成 273 秒单程）
- 每一小段现在单独计算通过时间；相邻段共用关节速度以确保命令位置/速度连续，再按控制周期重采样，并检查回放插值后的速度与加速度上界
- 保持现有命令速度、加速度与关节活动范围检查，不通过提高限速、强制失能或删掉反向采样来制造“200 秒”结果
- `planner_id=local_hermite`；GUI 会显示关节空间路径长度、压缩后的关键点数和预计耗时，旧原生程序没有该标识，将被提示重新编译
- 仍不能保证所有 30 秒/40 秒示教在 200 秒内完成：大幅动作、频繁反向、关节测量抖动均可能推高安全规划时间，若同一录制仍异常，须从实际任务目录的 `trajectory.csv` 和配置做定量诊断，不能猜测

## 周期超时与示教中断

- `INVALID_DT` 表示实际调用周期超过 `safety_policy.max_dt_s`，例如 `0.0221243 s > 0.02 s`，与 URDF 关节速度限位无关，应先检查控制线程调度、系统负载和总线阻塞，不能因为偶发超时就直接关闭安全检查
- Core 遇到真实 `FAULT` 时停止自动运动并锁存故障；关闭提醒窗口不会自动清除硬件故障，确认机械臂已受支撑、停稳且其他安全条件有效后，可从控制工作台手动请求清除故障；若故障保持或检查不通过，应人工排查，而非循环重试
- 拖拽示教过程中发生故障时，结束录制并保留已采集的有效控制周期样本；样本充足时保存 `trajectory.csv` 和 `interrupted.txt`，这代表**可供离线检查的故障前轨迹片段**，不是标定成功，加载后仍要检查 URDF/Core 指纹、采样完整性、位置范围、运动端点、姿态与反馈时效，并经人工确认才能回放
- 若故障前不足 20 个路径样本、采样不完整或文件保存失败，则不构造可回放轨迹，`frames.csv` 可作为离线诊断材料，但不能未经校验直接替代 `trajectory.csv`
- 等待回放确认阶段发生故障时，任务结束为 `FAILED`，已有的 `trajectory.csv` 不被删除，也不会自动驱动到保存的起点
- 工作台优先选择仓库 `.install/standalone/bin/serial_arm_terminal` 而不是系统 PATH 中可能残留的旧 Terminal；仍需按实际安装流程重新编译原生程序
